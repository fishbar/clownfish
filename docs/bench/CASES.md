# 基准题库与踩坑记录

五套题（外加一套第三方题库），共 13 道，全部离线可跑（只依赖 node / python3 / git），评分靠**智能体从未见过的隐藏测试**。
运行：`make bench`（第一套）、`node scripts/bench/run.mjs --suite phase2 --round N`（第二套）。

## 为什么这样设计

- **同一个模型后端驱动双方**（GLM 的 Anthropic 兼容代理）。比的是 harness——提示词、工具、委派、
  自我纠错——不是模型参数量。否则"谁赢"只是"谁的模型大"。
- **隐藏测试是评分的唯一依据。** 每道题都有一条"改可见测试来蒙混过关"的捷径，走了就是 0 分。
- **每轮从全新种子工作区开始。** 轮次之间不继承，改进才是可比的。
- **Claude Code 侧显式开启子代理**（`--append-system-prompt` 一句话）并隔离配置目录。Clownfish 的
  orchestrator 提示词天然在推委派，不给对手补这一句就是不公平比较。

## 第一套（phase1，`scripts/bench/tasks.mjs`）

| id | 考什么 | 埋的坑 |
|---|---|---|
| `async-queue` | 并发竞态定位与修复 + 补回归测试 | 顺序/并发上限/异常传播三者互相牵制；只让可见测试变绿的补法过不了隐藏的 40 任务压力测试 |
| `hot-path` | 性能改造（O(n²)→线性）且语义不变 | 相等总时长要按 session id 升序、脏数据要丢弃、不许跨调用缓存、不许改 benchmark 参数 |
| `god-module` | 大模块拆分，公共 API 一字不变 | 隐藏测试逐个断言 15 个导出的行为，并检查入口文件是否真的变成了门面（<60 行） |
| `broken-repo` | 运维排障：让 `npm test` 跑起来 | 四个互相独立的故障（缺 `type: module`、脚本指向不存在的目录、import 少扩展名、ESM 图里混了 CJS），只修一个不够 |
| `semver-range` | 按规格实现 semver 区间匹配 | 预发布版本规则是整道题的核心；只实现 `^`/`~` 能过可见测试，过不了隐藏的 7 组 |

## 第三套（phase3，`scripts/bench/tasks3.mjs`，宽任务）

前两套双方都打到满分，只剩耗时有区分度，所以补了"宽"而不只是"巧"的题——这才是编排/委派该发挥作用的场景。

| id | 考什么 | 埋的坑 |
|---|---|---|
| `callback-migration` | 13 个模块从 error-first 回调迁到 Promise | 三个非机械模块：重复回调必须幂等、参数校验必须**同步**抛而不是返回 rejected promise、并发池要同时保序+限流+失败即停；禁止 `promisify` 走捷径 |
| `api-versioning` | 8 个接口统一加分页 + v2 信封 | v1 形状一字不能变；游标必须是**位置**而非偏移（前面插入行不能导致跳行/重复）；非法参数要报错而不是静默夹取默认值 |

## 第二套（phase2，`scripts/bench/tasks2.mjs`，对标公开榜单家族）

| id | 对标 | 考什么 |
|---|---|---|
| `swe-patch` | SWE-bench | 给 issue + 复现测试，修状态机在"重试 × 取消 × 优先级"交汇处的缺陷；隐藏测试专查"修好复现却弄坏另外两个特性" |
| `terminal-ops` | Terminal-Bench | 从 `git reflog` 里救回被 `reset --hard` 丢掉的提交，并修好没有可执行位的 `run.sh`；隐藏测试校验救回来的是**原提交内容**而不是自己重写的 |
| `polyglot` | Aider Polyglot | 同一份区间代数规格，用 JS 和 Python 各实现一遍，两边都跑隐藏测试；禁止一边 shell 调另一边 |
| `security-fix` | SEC-bench | 目录穿越 + 原型污染两类洞一起修，且合法功能（嵌套 key、`proto` 这类普通字段名）不能被误伤 |

## 用量口径

两边的 token 都记，并归一到同一形状（`scripts/bench/usage.mjs`）：

- **Clownfish**：从会话 transcript 逐条 assistant 消息累加，**包含每个子代理自己的 transcript**——委派花掉的 token 仍然是这次运行花的。
- **Claude Code**：`--output-format json` 的聚合 usage 信封。
- `cacheHitRate = cacheRead / (input + cacheRead + cacheWrite)`，即提示 token 里免于重新处理的比例；输出 token 不参与，因为它从不可缓存。
- **金额不可比**：Clownfish 记录的 `cost` 来自 pi-ai 对配置模型 id 的价目表，而实际走的是 GLM 代理，那个数字不是真实花费。**只有 token 数两边可比。**

已有轮次用 `node scripts/bench/backfill-usage.mjs` 从磁盘上的 transcript 回填，不需要重跑任何智能体。

## 模型档位

`--claude-model <tier>` + `--claude-model-id <model>` 控制 Claude Code 的档位，两个别名环境变量由 runner 设置。
**档位不同的轮次不是同模型对比**，报告会在该轮标题下打警告横幅——差异里混进了模型能力，不能只当 harness 的差异读。
每次 `claude -p` 都是独立进程、独立 `CLAUDE_CONFIG_DIR`（按轮次+任务隔离）、无 `--resume`，绝不会续在已有会话上。

## 踩过的坑（harness 自身的）

1. **`node --test test/`（目录形式）在 Node 24 下会把目录当模块解析**，直接 `MODULE_NOT_FOUND`。
   第一轮因此把两边**都解决了的题判成失败**——clownfish 的 async-queue 其实连隐藏并发测试都过了。
   教训：验证器必须先在"已知正确解"上自检；现在统一用 `runSuite()` 显式枚举测试文件。
   为此给 runner 加了 `--rescore`：重跑验证而不重跑智能体，否则修一个验证器 bug 就要把整轮重烧一遍。
2. **JS 块注释里写 `round*/summary.json` 会提前闭合注释**，报错位置还在几十行之外。
3. **Node 24 默认用 spec reporter（`ℹ pass N`），不是 TAP（`# pass N`）。** 我按 TAP 解析计数，
   于是**所有隐藏测试恒判 0 通过**，两边的正确解全被判失败。现在统一加 `--test-reporter=tap`
   把报告格式钉死，而不是猜 Node 选了哪个。
4. **隐藏测试断言了参考实现根本没有的行为。** `broken-repo` 里我断言 "An Ode to Joy"，可种子代码的
   小词表里没有 `to`，正确答案应是 "An Ode To Joy"——题面又要求"不许改变行为"。两边都在为我的错误扣分。
   教训：隐藏测试必须先跑在**参考实现**上验证，而不是跑在"我以为的正确行为"上。
5. **题目会触顶。** phase1 第一轮双方都 19/19，题目失去区分度；继续在饱和题上跑第 2、3 轮没有信息量，
   所以把优化循环挪到更难的 phase2，并补了第 5 题。触顶本身是结论，不是失败。
6. **说好的"间歇失败"必须真的间歇。** `flaky-ci` 初版是必现失败，题面却写"三次一次"；核对后如实改写题面。
   出题人自己没跑过的描述不能进题库。
7. **隐藏测试不能钦定某一种解法。** `security-fix` 我断言 `put("__proto__", …)` 必须**抛异常**，
   但用 null 原型的索引把它**安全容纳**同样正确。改成断言安全属性本身（原型没被污染、存储仍可用）之后
   clownfish 从 1/2 变 2/2。教训：测"结果对不对"，不要测"是不是按我想的那样写"。
8. **隐藏测试自身要自洽。** `flaky-ci` 我用 `max: 5` 的缓存写了 20 条又断言全部可读——淘汰机制本就该丢，
   是我错。改成 `max: 100` 后 clownfish 从 3/4 变 4/4。
9. **种子必须先跑得起来。** `api-versioning` 初版里 `src/handlers/*.js` 写 `./data.js`，实际文件在上一层，
   种子直接 import 失败——等于逼智能体去修一个题面没提的 bug。
10. **于是加了出题人自检**：每道题声明 `expectDry`（空跑应得几分），`make bench-dry` 逐一核对，
    低了说明种子坏了、高了说明白送分，不符直接非零退出。三套题目前全部对得上。
11. **结构性检查会惩罚更好的设计（这是最贵的一课，前后犯了四次）。**
    `api-versioning` 我查"`src/handlers/` 里必须正好 8 个文件"且"每个文件都要出现 limit/cursor"。
    clownfish 把分页抽成共享的 `paginate.js` 给 8 个 handler 复用——**正确做法**——却因此被判两项失败，
    而它的行为规格是 8/8 全过的。同一家族的错误还有：钦定"必须抛异常"、断言参考实现没有的行为、
    自己写的隐藏测试内部矛盾。
    **规则：只测可观察行为，不测实现形状。** 想验"改动是否覆盖到全部 N 个对象"，就逐个跑它们的行为
    （比如"8 个资源的分页语义必须一致"），而不是数文件、grep 关键字。
12. **`make bench-dry` 默认写进 `round1`，把第一轮的真实产物覆盖了。** 空跑会重新播种工作区并改写结果，
    等于把已经花钱跑出来的证据擦掉。我没有伪造数据，而是用修好的验证器把第一轮**重跑**了一遍；
    同时把基线固定到 `round 0`，并在 runner 里加了护栏：dry run 若发现目标轮次已有真实运行，直接拒绝退出。
13. **`pkill -f "tsx server/index.ts"` 把基准自己的服务也杀了。** 我本想关掉手动开的 UI 服务，
    模式却同时匹配到基准正在用的 clownfish 服务，那一轮的 god-module 直接变成 `closed`。
    教训：在跑着后台实验时，杀进程的模式必须精确到端口或 PID，别用通配。
14. **对"确定性"题目，判定本身也必须确定。** `flaky-ci` 的时钟粒度探针原本循环 500 次，
    同一份代码 1 次判失败、4 次判通过——**验证器自己是 flaky 的**。改成循环 5 万次
    （让 `Date.now()` 方案必然踩到毫秒跳变、单调时钟方案必然安全）+ 隐藏套件连续 3 次全绿才算过，
    并**分别拿两个已知解法验证过判别器**（`performance.now()` 3/3 绿，`Date.now()` 1/3）。
15. **rescore 会把轮次元数据重置成当前命令行的默认值**，导致 round 5 的 opus 档被记成 sonnet。
    改成：rescore 保留原 summary 的模型/档位，且报告以**结果条目里记录的档位**为准，不信任 summary 头。
16. **n=1 分不清"更强"和"运气好"。** round 5 clownfish 在 `flaky-ci` 上丢一分，看着像能力差距；重复跑 6 次是 6/6，实际失败率约 1/8。
    任何"改进"的主张都必须移动一个**率**，为此加了 `scripts/bench/repeat.mjs`（同题重复 N 次，输出满分率 + 过程指标）。
    另外：罕见失败的统计功效极低，**要测的是过程指标**（有没有为缺陷造探针、有没有做独立验证），它每次运行都能观测。
17. **`--dry` 基线必须接近零分**：phase1 空跑 7/19（其中 hot-path 的 3 分是"种子语义本就正确"）、
    phase2 空跑 3/17、phase3 空跑 4/9。差值才是智能体的贡献。

## 第四套（phase4，`scripts/bench/tasks4.mjs`，考 harness 而不是考长度）

前三套都触顶（双方满分，只剩用时有区分度）。重跑一套已经打满的题不产生信息，所以这一套换了个思路：
**每道题都要求一种「harness 要么有、要么没有」的行为，缺了这个行为就是丢分，而不是变慢。**

| id | 要求的行为 | 埋的坑 | 分档 |
|---|---|---|---|
| `heisenbug` | **必须真的跑起来**。测试全绿，bug 只在一份 CI 日志里；不构造探针复现就找不到 | 三个独立缺陷：check-then-act 抢占、`nextRun` 用了 tick 开始时的旧时钟、异常后不释放。**修法本身是陷阱**——把调度串行化能消掉重复执行，但会挂在并发检查上；不用 `finally` 会挂在抛异常检查上 | 种子 2/5 · 串行化 3/5 · 少 finally 4/5 · 正解 5/5 |
| `perf-bisect` | **必须查历史**。回归的原因不在工作区，在 git log 里 | 引入回归的那个 commit 同时加了一个现在被依赖的功能。`git revert` 让可见测试变绿却丢功能；`git reset --hard` 还额外改写了历史 | 种子 4/5 · revert 4/5 · reset 3/5 · 正解 5/5 |
| `needle-in-haystack` | **必须定位，不能整篇重写**。6000 行生成代码里错了一个字符（`>=` 应为 `>`），失败信息只给一个对不上的总额，不指名规则 | 隐藏检查会逐条比对另外 299 条规则的源码形态：把文件重新生成一遍——哪怕行为全对——照样扣分 | 种子 1/4 · 重新生成 3/4 · 正解（改一个字符）4/4 |

三道题的**参考解和陷阱解都实测过**（见上表分档），所以「满分只有正解能拿到」不是设计意图而是验证过的事实。

**round 6 实测：这套题没有触顶。** 双方都是 13/14，而且**丢的是同一项**——`heisenbug` 里
那个没被 CI 日志提到的第三个缺陷（`nextRun` 用了 tick 开始时读到的旧时钟）。两边一起漏，
说明这一项是「难但公平」的彻底性检查，不是偏向某一方的机关。

| round 6 | clownfish | claude-code | 倍数 |
|---|---|---|---|
| 正确性 | 13/14 (93%) | 13/14 (93%) | — |
| 用时 | 266s | 1156s | 4.3× |
| token | 297k | 2050k | 6.9× |
| 费用 | ¥1.04 | ¥6.22 | 6.0× |

运行：`node scripts/bench/run.mjs --suite phase4 --round N`；`make bench-dry` 会连同前三套一起校准基线。

## 第五套（polyglot，`scripts/bench/polyglot.mjs`，**不是我们出的题**）

前四套的题和 harness 是同一批人写的。这对「改动前后自己跟自己比」没问题，但回答不了
「这个 harness 到底好不好」——坑是我们埋的，及格线也是我们划的。这一套没有这层耦合：
题目是 [Aider polyglot benchmark](https://github.com/Aider-AI/polyglot-benchmark)
（Exercism 里被 aider 选出来的 225 道，判分用每道题**上游自带的测试**）。

改动都摆在明处：

- **只跑 python / go / rust**。java 要 JDK、c++ 要 cmake、javascript 每题都要
  `npm install` jest+babel——带上它们量的是工具链而不是智能体。225 道里剩 100 道，
  所以**绝对分数不能和公开榜单比**（语言子集不同，模型后端也不同）。
- **上游的参考解 `.meta/example.*` 不进工作区**。
- **判分前把测试文件从原始 checkout 覆盖回去**，并额外报告它有没有被改过——测试就在
  工作区里，改测试变绿是最顺手的捷径。
- 抽样是题名的固定哈希，`--n 12` 每轮都是同样 12 道，轮次可比。

双向验过：未动的 stub 得 1/2（测试挂、但没篡改测试），抽样的 9 道**上游参考解全部 2/2**
——所以 runner 是真的在跑测试，不是见谁都给分。

| round 9（12 道，python/go/rust 各 4） | clownfish | claude-code | 倍数 |
|---|---|---|---|
| 正确性 | 24/24 (100%) | 24/24 (100%) | — |
| 用时 | 497s | 1064s | 2.1× |
| token | 846k | 3776k | 4.5× |
| 费用 | ¥2.80 | ¥10.58 | 3.8× |

**这套题在正确性上也触顶了**（两边全对），区分度同样只剩效率。这本身是个结论：
公开题库里"难"的那批，对当前模型的两个 harness 都不构成正确性挑战，
真正拉开差距的是走到答案要烧多少。

运行：`make bench-polyglot-fetch` 拉一次 checkout，然后 `make bench-polyglot ROUND=n N=12`。

## 第六套（phase5，`scripts/bench/tasks5.mjs`，长程构建）

phase4 难但**短**：每题都是一个缺陷，一口气解决。这一套故意做成**有次序**的——六个里程碑，
而且后面的里程碑会推翻前面的自然写法：

- **M2（并发上限）** 推翻 M1 里那个顺序 for 循环；
- **M4（重试）** 推翻"一抛异常就把下游标 skipped"的 M3——重试后成功的任务不该跳过任何东西；
- **M5（从 journal 恢复）** 推翻把完成状态和重试计数只放在局部变量里的设计，而 M1–M4 天然
  会引导你那样写。

所以按里程碑顺序一路写下来的实现，**必须回头返工自己已经写完的状态设计**。被测的就是这个：
能不能在长程里守住一个设计，而不是解六道彼此独立的题。

计分刻意做细（8 项独立检查），因为 phase1–4 全都饱和在"两边都满分"，而饱和的基准测不出东西。

**实测分档**（都跑过，不是设计意图）：

| 实现 | 分数 | 挂在哪 |
|---|---|---|
| 未动的 stub | **0/8** | 全挂 |
| 顺序执行（M1 的循环留到最后） | 6/8 | M2、integration |
| 一抛异常就跳下游（没等重试跑完） | 7/8 | M4 |
| 不支持 resume（状态只在局部变量） | 6/8 | M5、integration |
| 参考实现 | **8/8** | — |

种子 0/8 意味着这套题**头顶空间最大**——不像 phase4 有几道种子就已经 4/5。
运行：`node scripts/bench/run.mjs --suite phase5 --round N`。

### phase5 实测（每边跑 3 次，n=1 的问题这次补上了）

第一次跑 n=3 就把**我自己的 bug** 跑了出来：clownfish 三次是 8/8、8/8、**5/8**，那次 5/8 撞满
900s 超时却只烧了 76k token。查下去是 prompt 里写的 `node --test test/` 在这台机器上根本跑不通，
子代理拿整整 900s 在跟评测台搏斗。**全部五套共 11 处都有这个毛病**，已修，并加了守卫
（`--dry` 会把 prompt 里引用的每条命令在种子工作区真跑一遍）。那份受污染的样本归档在
`.bench/repeat/phase5-BROKEN-PROMPT/`，没有删。

修好 prompt 之后重跑，两边各 3 次：

| | clownfish | claude-code |
|---|---|---|
| 正确性 | **8/8 · 8/8 · 8/8** | **8/8 · 8/8 · 8/8** |
| 用时（中位） | 384s（248–533） | 853s（527–900） |
| token（中位） | 425k（194–526） | 920k（851–989） |
| 费用（中位） | ¥1.63 | ¥3.17 |

**结论：连这道长程题也在正确性上饱和了。** 我特意做成"后面推翻前面"、8 项细分检查、
